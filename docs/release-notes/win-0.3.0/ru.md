> **Заменена версией [0.3.1](https://github.com/gpasa/treelevel-tools/releases/tag/win-0.3.1).** Эта версия распознаёт образ только под тегом `:0.3.0`; 0.3.1 принимает и `:latest` — тот, который скачивает `docker pull` без номера.

Ядро, которое запускает генераторы Монте-Карло для TreeLevel в Windows. Устанавливается распаковкой архива в `%LOCALAPPDATA%\Programs` — ни установщика, ни записей в реестре.

Выберите архив для своей машины: `arm64` для ПК Copilot+ или планшета на ARM, `x64` во всех остальных случаях. В случае сомнений x64 работает и на ARM, под эмуляцией.

**Что содержит архив**: ядро и модуль Pythia 8, скомпилированный для этой архитектуры. Herwig, Sherpa, WHIZARD и CalcHEP идут через образ контейнера `ghcr.io/gpasa/treelevel-tools`, которому нужен Docker. Скачивайте его **с номером**:

```
docker pull ghcr.io/gpasa/treelevel-tools:0.3.0
```

Эта версия ядра распознаёт только этот тег: образ, скачанный без номера (то есть `:latest`), действительно есть на машине, но TreeLevel не предлагает его генераторы. Оба тега обозначают один и тот же образ; если у вас уже есть `latest`, команда выше лишь добавит тег. Docker Desktop должен быть запущен, когда стартует TreeLevel.

### Пять генераторов, два семейства

**Pythia 8** и **Herwig 7** достраивают партонные события, которые им передаёт TreeLevel: ливень, адронизация, распады.

У **Sherpa 3**, **WHIZARD 3** и **CalcHEP 3** нет считывателя Les Houches — они сами вычисляют процесс, описанный диаграммой. Поэтому протокол передаёт им, наряду с событиями, описание процесса (пучки, энергии, конечное состояние, порядки по константам связи).

### Измерено: e⁻e⁺ → W⁺W⁻ при 200 GeV

| программа | σ |
|---|---|
| TreeLevel | 19,22 pb |
| WHIZARD 3.1.6 | 19,441 ± 0,006 pb |
| CalcHEP 3.9.2 | 20,42 pb |
| Sherpa 3.0.5 | 18,2 ± 1,1 pb |

Расхождения объясняются выбором схемы констант связи, а не ошибками.

### Новое в этой версии

- **Режим коллайдера.** Генератор получает только пучки и энергию, никогда — конечное состояние: он производит всю смесь, как настоящий ускоритель, а TreeLevel затем подсчитывает события, несущие сигнатуру нарисованного процесса, — так сечение измеряется, а не вычисляется. Шесть семейств каналов, в том числе жёсткая КХД, фоторождение и полное сечение. Пока только Pythia 8.
- **Две конфигурации ускорителя, собранные вместе.** Лептонный пучок входит либо как лептон, либо как поток фотонов, который он излучает, но никогда не как то и другое в одном розыгрыше: ядро разыгрывает оба варианта и оставляет от каждого долю, которая соответствует его сечению.
- **Сообщаемое сечение — это сечение после последнего события.** Pythia нормирует после своего цикла; управляющая программа записывала текущую оценку, ошибочную на 12 % при нескольких сотнях событий.
- **Программа называется TreeLevel Tools**, а исполняемый файл — `treelevel-tools.exe`. Она содержит уже не только программы Монте-Карло.

### Также

- Задания пронумерованы, снабжены отметкой времени и хранятся в списке, который TreeLevel открывает снова.
- Сечение считывается там, куда его помещает каждый генератор: строка `C` в Asciiv3, атрибут `GenCrossSection` или таблица интегрирования.

### Известная проблема

Если Sherpa работает в собственной установке WSL, а не в образе, его сечение на лептонных пучках получается завышенным: начальное излучение КЭД там остаётся включённым, и e⁻e⁺ → b b̄ при 200 GeV даёт около пятнадцати пикобарн вместо 3,2. Через образ `ghcr.io/gpasa/treelevel-tools` это исправлено.
