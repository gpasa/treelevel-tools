> **[0.3.1](https://github.com/gpasa/treelevel-tools/releases/tag/win-0.3.1) に置き換えられました**。このバージョンは、タグ `:0.3.0` のイメージしか認識しません。0.3.1 は、番号なしの `docker pull` が取得する `:latest` も受け付けます。

Windows 上の TreeLevel のためにモンテカルロ生成器を動かすエンジンです。書庫を `%LOCALAPPDATA%\Programs` に展開するだけでインストールできます——インストーラもなく、レジストリにも何も残しません。

お使いのマシンに合う書庫を選んでください：Copilot+ PC や ARM タブレットなら `arm64`、それ以外はすべて `x64`。迷ったら、x64 版も ARM でエミュレーションで動きます。

**書庫の内容**：エンジンと、このアーキテクチャ向けにコンパイルされた Pythia 8 モジュール。Herwig、Sherpa、WHIZARD、CalcHEP はコンテナイメージ `ghcr.io/gpasa/treelevel-tools` を通ります。それには Docker が必要です。**番号付きで** pull してください：

```
docker pull ghcr.io/gpasa/treelevel-tools:0.3.0
```

このバージョンのエンジンはこのタグしか認識しません：番号なしで pull したイメージ（つまり `:latest`）はマシンに確かにありますが、TreeLevel はその生成器を提示しません。二つのタグは同じイメージを指しています。すでに `latest` がある場合、上のコマンドはタグを加えるだけです。TreeLevel の起動時に Docker Desktop が動いている必要があります。

### 五つの生成器、二つの系統

**Pythia 8** と **Herwig 7** は、TreeLevel が渡すパートンのイベントに肉付けします：シャワー、ハドロン化、崩壊。

**Sherpa 3**、**WHIZARD 3**、**CalcHEP 3** には Les Houches リーダーがありません——ダイアグラムが表す過程を自ら計算します。そこでプロトコルは、イベントと並べて過程の記述（ビーム、エネルギー、終状態、結合の次数）を渡します。

### 測定：200 GeV での e⁻e⁺ → W⁺W⁻

| エンジン | σ |
|---|---|
| TreeLevel | 19.22 pb |
| WHIZARD 3.1.6 | 19.441 ± 0.006 pb |
| CalcHEP 3.9.2 | 20.42 pb |
| Sherpa 3.0.5 | 18.2 ± 1.1 pb |

差は結合定数のスキームの選び方によるもので、誤りではありません。

### このバージョンの新機能

- **コライダーモード**。生成器が受け取るのはビームとエネルギーだけで、終状態は決して受け取りません：本物の加速器のように混合全体を生み出し、TreeLevel はそのあと、描かれた過程の特徴を持つイベントを数えます——断面積を計算する代わりに測定するのです。六つのチャンネル群があり、ハード QCD、光生成、全断面積を含みます。今のところ Pythia 8 のみです。
- **二つの加速器構成の組み合わせ**。レプトンビームはレプトンとして、あるいはそれが放射する光子のフラックスとして入り、同じ試行で両方になることはありません：エンジンは両方を生成し、それぞれの断面積に見合った割合を各々から残します。
- **報告される断面積は最後のイベントの後の値です**。Pythia はループの後で規格化します。ドライバは途中の推定値を書いており、数百イベントでは 12% ずれていました。
- **プログラムの名前は TreeLevel Tools**、実行ファイルは `treelevel-tools.exe` です。もはやモンテカルロエンジンだけを収めるものではありません。

### その他

- ジョブには番号と日時が付き、一覧に保存され、TreeLevel が開き直せます。
- 断面積は各生成器が置く場所から読み取ります：Asciiv3 の `C` 行、`GenCrossSection` 属性、または積分表。

### 既知の問題

Sherpa がイメージではなく個人の WSL 環境で動く場合、レプトンビームでの断面積が高く出すぎます：そこでは QED の始状態放射がオンのままで、200 GeV での e⁻e⁺ → b b̄ が 3.2 ではなく十五ピコバーンほどになります。イメージ `ghcr.io/gpasa/treelevel-tools` を通せば、これは修正されています。
