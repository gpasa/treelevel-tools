Ядро, которое запускает генераторы Монте-Карло для TreeLevel в Windows. Устанавливается распаковкой архива в `%LOCALAPPDATA%\Programs` — ни установщика, ни записей в реестре. **Чтобы обновить** предыдущую версию: закройте TreeLevel и распакуйте архив в то же место, заменив файлы.

Выберите архив для своей машины: `arm64` для ПК Copilot+ или планшета на ARM, `x64` во всех остальных случаях. В случае сомнений x64 работает и на ARM, под эмуляцией.

**Что содержит архив**: ядро и модуль Pythia 8, скомпилированный для этой архитектуры. Herwig, Sherpa, WHIZARD и CalcHEP идут через образ контейнера, которому нужен Docker Desktop:

```
docker pull ghcr.io/gpasa/treelevel-tools
```

Больше ничего делать не нужно: TreeLevel сам создаёт временный контейнер для каждого задания. Docker Desktop должен быть запущен, когда стартует TreeLevel; тогда появляются генераторы образа с пометкой «(Docker)».

**У ядра нет окна.** Его запускает TreeLevel, всякий раз, когда это нужно. Если дважды щёлкнуть `treelevel-tools.exe`, Windows SmartScreen предупредит о нераспознанном приложении — ядро не подписано, — а после предупреждения консоль покажет инструкцию по использованию и закроется. Это нормально и ни на что не влияет: вам никогда не нужно запускать его самостоятельно.

### Исправления в этой версии

- **Образ, скачанный без номера, распознаётся.** 0.3.0 распознавала только тег `:0.3.0`; между тем команда, которую предлагает страница пакета, и та, которую набирают все, скачивает `:latest`. Образ был на машине, отвечал при запуске вручную, и всё же TreeLevel предлагал только Pythia. Оба тега обозначают один и тот же образ, и теперь распознаются оба.
- **Sherpa на лептонных пучках**, когда он работает вне образа: его сечение больше не завышено начальным излучением КЭД (около пятнадцати пикобарн вместо 3,2 для e⁻e⁺ → b b̄ при 200 GeV). Путь, который от этого зависел, — Sherpa, самостоятельно установленный в WSL, — будет удалён в одной из следующих версий: предусмотренный путь — Docker.

### Пять генераторов, два семейства

**Pythia 8** и **Herwig 7** достраивают партонные события, которые им передаёт TreeLevel: ливень, адронизация, распады.

У **Sherpa 3**, **WHIZARD 3** и **CalcHEP 3** нет считывателя Les Houches — они сами вычисляют процесс, описанный диаграммой. Поэтому протокол передаёт им, наряду с событиями, описание процесса (пучки, энергии, конечное состояние, порядки по константам связи).

### Измерено: e⁻e⁺ → W⁺W⁻ при 200 GeV

| программа | σ |
|---|---|
| TreeLevel | 19,22 pb |
| WHIZARD 3.1.6 | 19,441 ± 0,006 pb |
| CalcHEP 3.9.2 | 20,42 pb |
| Sherpa 3.0.5 | 18,2 ± 1,1 pb |

Расхождения объясняются выбором схемы констант связи, а не ошибками.

### Напоминание: что принесла 0.3.0

- **Режим коллайдера.** Генератор получает только пучки и энергию, никогда — конечное состояние: он производит всю смесь, как настоящий ускоритель, а TreeLevel затем подсчитывает события, несущие сигнатуру нарисованного процесса, — так сечение измеряется, а не вычисляется. Шесть семейств каналов, в том числе жёсткая КХД, фоторождение и полное сечение. Пока только Pythia 8.
- **Две конфигурации ускорителя, собранные вместе.** Лептонный пучок входит либо как лептон, либо как поток фотонов, который он излучает, но никогда не как то и другое в одном розыгрыше: ядро разыгрывает оба варианта и оставляет от каждого долю, которая соответствует его сечению.
- **Сообщаемое сечение — это сечение после последнего события.** Pythia нормирует после своего цикла; управляющая программа записывала текущую оценку, ошибочную на 12 % при нескольких сотнях событий.
- **Программа называется TreeLevel Tools**, а исполняемый файл — `treelevel-tools.exe`.
- Задания пронумерованы, снабжены отметкой времени и хранятся в списке, который TreeLevel открывает снова; сечение считывается там, куда его помещает каждый генератор.

TreeLevel Tools распространяется под GPL v3 или более поздней (см. `LICENSE.txt` в архиве); у каждого генератора своя лицензия, см. ниже.
