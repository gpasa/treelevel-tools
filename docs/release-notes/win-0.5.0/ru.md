Ядро, которое запускает генераторы Монте-Карло для TreeLevel 1.4 в Windows (и по-прежнему для 1.3). Устанавливается распаковкой архива в `%LOCALAPPDATA%\Programs` — ни установщика, ни записей в реестре. **Чтобы обновить** предыдущую версию: закройте TreeLevel и распакуйте архив в то же место, заменив файлы.

Выберите архив для своей машины: `arm64` для ПК Copilot+ или планшета на ARM, `x64` во всех остальных случаях. В случае сомнений x64 работает и на ARM, под эмуляцией.

**Что содержит архив**: `treelevel-tools.exe`, который запускает TreeLevel; `treelevel-engine.exe` — ядро, которое пишет карточку каждого генератора и ведёт его; модуль Pythia 8, скомпилированный для этой архитектуры; `CREDITS.md`. Herwig, Sherpa, WHIZARD и CalcHEP идут через образ контейнера, которому нужен Docker Desktop:

```
docker pull ghcr.io/gpasa/treelevel-tools:latest
```

Больше ничего делать не нужно: TreeLevel сам создаёт временный контейнер для каждого задания. Docker Desktop должен быть запущен, когда стартует TreeLevel; тогда появляются генераторы образа с пометкой «(Docker)».

**У ядра нет окна.** Его запускает TreeLevel, всякий раз, когда это нужно. Если дважды щёлкнуть `treelevel-tools.exe`, Windows SmartScreen предупредит о нераспознанном приложении — ядро не подписано, — а после предупреждения консоль покажет инструкцию по использованию и закроется. Это нормально и ни на что не влияет.

### Что меняется

- **Зона взаимодействия в масштабе фемтометра.** Для TreeLevel 1.4 управляющая программа Pythia умеет помещать каждое партонное взаимодействие в область перекрытия двух адронов, а каждый адрон — туда, где разорвалась его струна (ключ задания `spaceTime`: `PartonVertex:setVertex`, `Fragmentation:setVertices`). Для каждого партона она записывает его цветовой поток и статус Pythia, а для каждой частицы, родившейся не в своей вершине, — её собственное место рождения; именно это рисуют увеличенное сечение и вид 3D в TreeLevel 1.4. Это модель генератора, а не результат измерения.
- **Единое смещение области светимости.** С этими положениями Pythia смещала адроны дважды; теперь управляющая программа сама размещает событие одним вектором. Без ключа ничего не меняется.
- **Ядро сообщает, что оно умеет**: `treelevel-tools capabilities` объявляет `spaceTimeGenerators` (нативную Pythia, когда её управляющая программа отвечает «spacetime», и то, что объявляет образ). TreeLevel 1.4 показывает флажок «положения в зоне взаимодействия», только если генератор там указан.
- **Совместимо с TreeLevel 1.3**: задание без ключа `spaceTime` выполняется точно так же, как с 0.4.0.
- **Образ Docker 0.5** выйдет следом: до тех пор `:latest` — это образ 0.4.0, и Herwig, Sherpa, WHIZARD и CalcHEP работают в нём как раньше; зона взаимодействия идёт через нативную Pythia из этого архива.
- **То же ядро, что и в `mac-0.5.0`**: та же управляющая программа Pythia (`Backends/pythia/main.cpp`), те же ключи задания, те же записываемые атрибуты.
