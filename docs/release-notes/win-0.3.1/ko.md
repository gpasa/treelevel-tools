Windows에서 TreeLevel을 위해 몬테카를로 생성기를 돌리는 엔진입니다. 압축 파일을 `%LOCALAPPDATA%\Programs`에 풀기만 하면 설치됩니다—설치 프로그램도 없고 레지스트리에 남는 것도 없습니다. 이전 버전을 **업데이트하려면** TreeLevel을 닫고, 압축 파일을 같은 자리에 풀어 파일을 덮어쓰십시오.

여러분의 컴퓨터에 맞는 압축 파일을 고르십시오: Copilot+ PC나 ARM 태블릿이면 `arm64`, 그 밖에는 모두 `x64`. 헷갈릴 때는 x64판도 ARM에서 에뮬레이션으로 돌아갑니다.

**압축 파일의 내용**: 엔진과, 이 아키텍처용으로 컴파일된 Pythia 8 모듈. Herwig, Sherpa, WHIZARD, CalcHEP은 컨테이너 이미지를 거치며, 이 이미지에는 Docker Desktop이 필요합니다:

```
docker pull ghcr.io/gpasa/treelevel-tools
```

더 할 일은 없습니다: TreeLevel이 작업마다 일회용 컨테이너를 직접 만듭니다. TreeLevel이 시작할 때 Docker Desktop이 실행 중이어야 하며, 그러면 이미지의 생성기가 ‘(Docker)’ 표시를 달고 나타납니다.

**엔진에는 창이 없습니다.** TreeLevel이 필요할 때마다 실행합니다. `treelevel-tools.exe`를 더블클릭하면 Windows SmartScreen이 인식할 수 없는 앱이라고 경고합니다—엔진은 서명되어 있지 않습니다—. 경고를 넘기면 콘솔이 사용법을 보여 주고 닫힙니다. 정상이며, 아무 영향도 없습니다: 여러분이 직접 실행할 일은 전혀 없습니다.

### 이번 버전의 수정 사항

- **번호 없이 받은 이미지를 인식합니다.** 0.3.0은 `:0.3.0` 태그만 인식했습니다. 그런데 패키지 페이지가 제시하는 명령, 그리고 누구나 입력하는 명령은 `:latest`를 받습니다. 이미지는 컴퓨터에 있었고 손으로 실행하면 응답했는데도, TreeLevel은 Pythia만 제공했습니다. 두 태그는 같은 이미지를 가리키며, 이제 둘 다 인식됩니다.
- **렙톤 빔에서의 Sherpa**, 이미지 밖에서 실행될 때: 그 단면적이 더 이상 QED 초기 상태 복사로 부풀려지지 않습니다(200 GeV에서 e⁻e⁺ → b b̄에 대해 3.2 대신 열다섯 피코반가량). 이것에 의존하던 경로—WSL에 직접 설치한 Sherpa—는 다음 버전에서 제거됩니다: Docker가 예정된 경로입니다.

### 생성기 다섯, 두 계열

**Pythia 8**과 **Herwig 7**은 TreeLevel이 넘겨주는 파톤 사건을 완성합니다: 샤워, 강입자화, 붕괴.

**Sherpa 3**, **WHIZARD 3**, **CalcHEP 3**에는 Les Houches 판독기가 없습니다—다이어그램이 기술하는 과정을 직접 계산합니다. 그래서 프로토콜은 사건과 나란히 과정의 기술(빔, 에너지, 최종 상태, 결합 차수)을 이들에게 전달합니다.

### 측정: 200 GeV에서 e⁻e⁺ → W⁺W⁻

| 엔진 | σ |
|---|---|
| TreeLevel | 19.22 pb |
| WHIZARD 3.1.6 | 19.441 ± 0.006 pb |
| CalcHEP 3.9.2 | 20.42 pb |
| Sherpa 3.0.5 | 18.2 ± 1.1 pb |

차이는 결합 스킴의 선택에서 오는 것이지, 오류가 아닙니다.

### 다시 보기: 0.3.0이 가져온 것

- **충돌기 모드.** 생성기는 빔과 에너지만 받을 뿐 최종 상태는 결코 받지 않습니다: 진짜 가속기처럼 혼합 전체를 만들어 내고, TreeLevel은 그다음 그려진 과정의 특징을 지닌 사건을 셉니다—단면적을 계산하는 대신 측정하는 것입니다. 채널 계열은 여섯 가지이며, 그중에는 경성 QCD, 광생성, 전체 단면적이 있습니다. 지금은 Pythia 8만 해당합니다.
- **두 가지 가속기 구성의 조합.** 렙톤 빔은 렙톤으로, 또는 그것이 복사하는 광자 선속으로 들어가며, 한 번의 추출에서 둘 다가 되는 일은 없습니다: 엔진은 둘 다 추출하고, 각각의 단면적에 해당하는 몫을 각각에서 남깁니다.
- **보고되는 단면적은 마지막 사건 이후의 값입니다.** Pythia는 루프가 끝난 뒤에 정규화합니다. 드라이버는 진행 중인 추정값을 쓰고 있었고, 이는 수백 개 사건에서 12% 어긋났습니다.
- **프로그램 이름은 TreeLevel Tools**, 실행 파일은 `treelevel-tools.exe`입니다.
- 작업에는 번호와 시각이 매겨지고 목록에 보관되며, TreeLevel이 다시 열 수 있습니다. 단면적은 각 생성기가 두는 곳에서 읽습니다.
